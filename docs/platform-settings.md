# 平台设置

入口：平台管理 → **平台设置**（`/settings`），提供基础信息、集成配置、用户与角色、运行信息四个分类。默认只向 Super Admin 开放。页面根据细粒度平台权限显示分类，所有请求再次从数据库解析当前活动用户和授权。

## 基础信息和登录公告

维护平台名称（2–64 字）、平台说明（最多 240 字）、登录公告（最多 1000 字）和管理员联系方式（最多 160 字）。名称同步用于导航、登录页和浏览器标题；说明、公告和联系方式显示在登录页，**全部是登录前公开内容**，不能填写内部凭据或敏感信息。

说明和公告支持纯文本换行，不解释 HTML/Markdown、不自动生成链接；清空公告即可隐藏。保存后本浏览器立即生效，其他浏览器重新加载或在缓存过期后重新聚焦时更新。公开信息读取失败时回退到默认品牌和联络提示，不阻塞登录表单。只提供四个公开字段，不返回修订、运行环境、认证配置、端点或凭据。

基础信息和 AI 设置共用一个单例 `platform_settings` 记录及修订号。保存必须提交当前修订，过期返回 409；变更和审计在同一 SQLite 事务提交，审计失败会回滚。原生 Collection API 全部锁定，没有通过浏览器直接写 Collection 的旁路。

## 集成配置

状态来自当前进程加载的配置，涵盖平台密码、PAM、LDAP、Slurm 连接方式、Prometheus/DCGM、Linux 用户来源与 AI；**已加载不等于已验证连通**。查询不探测第三方服务、不执行系统命令，不返回配置路径、密钥、LDAP 唯一标识或原始环境变量。

PAM、LDAP、Slurm、监控和 Linux 来源的配置、证书以及第三方组件仍由服务器管理员维护。集群连接编辑沿用现有“集群配置”页面；目录服务、Munge、Slurm 等的安装和维护不由本项目接管。

AI 支持在此页面编辑启用状态、服务名称、完整 Chat Completions 接收地址、模型名、集群允许列表、超时和输出预算。允许集群必须确实存在，无通配符，最多 100 个。即使停用，地址也不得包含用户名、密码、查询参数或 fragment。启用时复用既有 HTTPS、证书、回环 HTTP、受保护文件及预算校验。先核对接收地址、模型、范围，再输入 `APPLY AI` 确认；**保存配置不调用模型**。

密钥与自定义 CA 仍从服务器 `SLURM_CONSOLE_AI_CONFIG` 指向的受保护 JSON 中引用；页面只能看到“已引用/未配置”的状态，不能读取、上传或改写文件路径和内容。没有密钥的服务可直接保存并启用非敏感配置；需要密钥时管理员须先在服务器配置 `apiKeyFile`（及可选 `caFile`），重启应用后再启用。不得将密钥填到服务名称、地址或模型字段。

配置优先级：首次没有平台覆盖时使用服务器 JSON；页面保存后，数据库的非敏感 AI 配置优先，服务器文件继续提供密钥和 CA 引用。基础设置不影响 AI 配置。重启会重新载入数据库覆盖，因此仅修改服务器 JSON 的模型/地址不再覆盖页面已保存的值；界面明确标注“服务器配置/平台保存配置”。

AI 保存与审计先原子提交，再在当前进程切换服务；写操作串行且有修订校验，避免运行态倒序。切换使旧预览失效，并中止旧服务请求；已发出的请求无法撤回，旧响应不得展示为新配置的结果。原有逐次证据预览、用户确认、权限检查、预算和不自动重试规则继续生效。操作记录只保存非敏感配置，不保存凭据引用、提示或答案。详见 [AI 运维辅助](ai-assistance.md)。

## 用户与角色

用户列表支持按邮箱、显示名、系统用户名进行字面搜索及服务端分页；API 还支持认证来源和活动状态筛选。返回字段只包含 ID、邮箱、显示名、用户名、认证来源、活动状态、管理修订和更新时间。

可以创建：

- **平台密码账户**：使用邮箱登录，密码至少 12 个字符且不超过 71 字节；只接收一次，不返回或写入审计。生产使用现有 HTTPS 入口。
- **PAM 账户关联**：关联已存在并通过 PAM account 检查的非 root 系统用户名，不接收其系统密码。
- **LDAP 账户关联**：通过当前受保护配置查找已存在且符合准入条件的目录用户，固定其唯一标识，不接收目录密码、不向浏览器返回目录唯一标识。

创建后账户活动但没有角色，不自动建立 Slurm 身份或扩大 Slurm 原生权限。页面可更新显示名称以及停用/启用；先核对用户并输入 `UPDATE USER`。活动状态变化会轮换平台令牌密钥，已发令牌永久失效，重新启用后也不能复用旧令牌。外部账户仍须通过其系统/目录策略。页面不提供密码重置、删除用户、修改邮箱或切换现有认证来源；现有受信任本地关联命令继续可用。

角色目录展示已有角色及各自权限。角色定义由服务器迁移维护；页面可授予/撤销已有角色，不编辑角色定义。默认角色为 Super Admin、Cluster Admin、Operator、Viewer。平台角色不得携带集群，集群角色必须指定一个存在的集群。每次变更展示用户、角色和实际范围，并输入 `CHANGE ACCESS`；Super Admin 的全平台管理能力单独提示。

保护措施：不能停用当前登录账户；不能停用或撤销最后一个活动 Super Admin；管理员保护与目标修订在事务内复查，并发撤权也保留活动管理员。用户修改和角色绑定共享用户管理修订；本地创建、身份关联及角色 CLI 也更新修订。旧表中已有用户从修订 0 开始。创建、修改、授予、撤销均与审计同事务，失败不留下无审计变更。

修改当前用户权限后重新读取权威授权并清理客户端旧查询缓存；返回不得恢复已退出或切换的会话。服务器每次仍独立鉴权，不信任客户端显示或 JWT 中的角色。受信任 root CLI 作为应急管理通道保留，页面的误操作保护不限制 root 的恢复能力。

目录有显式上限：200 个角色、每角色 1000 个权限、1000 个授权集群、每用户每类 1000 个角色绑定；超过上限返回错误，不静默截断。

## 权限与 API

| 功能 | 平台权限 |
|---|---|
| 公开品牌与公告 | 无，固定字段白名单 |
| 查看基础信息、集成状态、AI 设置和运行信息 | `platform.settings.read` |
| 修改基础设置和 AI 配置 | `platform.settings.read` + `platform.settings.manage` |
| 用户查询、创建、显示名和活动状态修改 | `platform.users.manage` |
| 查看角色/权限目录和授权集群目录 | `platform.roles.manage` |
| 查看及修改用户角色绑定 | `platform.users.manage` + `platform.roles.manage` |

两个新增 settings 权限仅默认绑定 Super Admin；原有用户和授权管理权限的默认绑定保持不变。Cluster Admin、Operator、Viewer 不会继承平台管理权限。

OpenAPI 0.31.0 新增 13 个操作：

```http
GET   /api/v1/platform-info
GET   /api/v1/platform-settings
PATCH /api/v1/platform-settings
GET   /api/v1/platform-settings/ai
PATCH /api/v1/platform-settings/ai
GET   /api/v1/platform-settings/runtime
GET   /api/v1/platform-users?page=1&perPage=20&q=...&source=...&active=true
POST  /api/v1/platform-users
PATCH /api/v1/platform-users/{userId}
GET   /api/v1/platform-users/{userId}/roles
POST  /api/v1/platform-users/{userId}/roles
POST  /api/v1/platform-users/{userId}/roles/remove
GET   /api/v1/platform-role-catalog
```

写入使用完整 JSON，最多 16 KiB，拒绝未知字段、重复键、空值、尾随 JSON 和未知/重复查询参数。所有运行信息仅供平台管理员读取，包括构建修订、是否含未提交变更、Go 版本、OS/架构、进程启动时间、SQLite 和 root 执行状态。备份、恢复、升级和重启继续使用服务器维护工具，本页不伪造其健康或执行结果。
