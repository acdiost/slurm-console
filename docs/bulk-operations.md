# 批量操作

作业页增加批量取消，节点页的多选 Drain/Resume 改由同一服务端协调器执行；单项接口继续保留。本项只组合已实现的控制动作，不扩大作业身份范围或节点控制能力。

## 选择与确认

每批一个集群、一个动作、1–10 个明确且不重复的目标。作业仅限数字 Job ID，节点仅限实际节点名称；拒绝 ALL、范围、逗号选择器、数组和异构作业、root 作业，以及未知信号/节点属性。作业仍须显式关联 Slurm 身份，own 范围同时匹配用户名和 UID。Slurm 仍按固定连接身份决定上游权限。

页面仅选择当前页；翻页、筛选、排序或切换集群后选择失效，列表刷新移除已不可见或非活动作业。打开批量确认后绕过列表缓存逐项读取最新状态，任一项目不允许或读取失败时，整批不提供执行编号，必须调整目标并重新校验，不自动选择“允许项”。批量确认输入 `CANCEL N`、`DRAIN N` 或 `RESUME N` 和 2–300 字单行统一原因；单节点原有完整名称确认保持不变。

确认上下文绑定当前平台用户、集群、动作和完整目标集合，在服务端保存各单项确认，浏览器不能替换目标或取得单项 proof。有效期最多 2 分钟；每项仍独立绑定资源身份、状态、关联及连接修订。等待期间改变状态、撤权、停用用户、改动配置或确认过期，都会在实际发送前逐项复查并拒绝相应目标。

## 执行与结果

批量执行接口仅接受确认编号、确认短语和原因，先返回 processing 进度，由服务端继续执行。最多两个准备/执行/恢复读取请求占用协调槽，全部批次共用三个目标工作槽，单项控制服务保留原有四槽限制。手动单项操作占用资源时，批量项目可能得到 busy，明确显示为未完成，不自动重试。

每个真实控制请求继续由既有 jobcontrol/nodecontrol 写入独立 `operation_audits` 意图后发送一次，再读取核实结果。操作原因和执行请求编号随每项保存；同一次确认重复提交相同内容仅返回当前结果，内容变更拒绝。浏览器断开不取消已接受的批次；服务停止时未执行项目不自动继续。

允许部分成功；某项状态变化或被拒绝不回滚、重新发送或扩大其他项。确认过期可能使后排目标不执行，即使前排项目已经完成。执行结束的 completed 仅表示协调器结束，不表示所有 Slurm 控制均成功。

| 项目状态 | 含义 |
| --- | --- |
| ready | 已读取准备信息，等待明确确认 |
| processing | 已接受协调，等待复查/执行，不能证明已送达 Slurm |
| confirmed | 已回读核实目标状态 |
| accepted | Slurm 已受理，最终状态尚待只读核实 |
| failed | 明确未完成或未发送；不自动重发 |
| unknown | 不能确定结果，须核对记录和资源状态 |

页面保存批次编号及最多十个逐项操作编号至 URL，关闭后可只读刷新结果。上下文存在时保留没有进入持久意图的明确拒绝；对于 accepted/unknown，通过逐项审计进行只读核实。刷新页面不会调用执行接口。

**上下文不是持久任务队列。** 未执行上下文最多保留到确认过期，已执行上下文在内存中保留约 30 分钟，最多 64 个/8 MiB；单目标确认信息 64 KiB。服务重启会丢失这些上下文，但每项已持久化的操作审计保留。页面可退回逐项编号读取；没有审计的项目可能尚未送达、已被拒绝或结果待核实，不凭空补写成功或重新发送。长时间运行的准备/执行也受每项原有超时及确认期限约束。

## 平台接口

前缀 `/api/v1/clusters/{clusterId}/bulk-control`。要求活动用户、相应集群读取权限和执行动作；不增加隐式授权或新的 Slurm 管理身份。

| 方法与路径 | 输入与响应 |
| --- | --- |
| `POST /prepare` | `{action,targets}`；action 为 jobs.cancel/nodes.drain/nodes.resume；返回 allowed、逐项准备信息及短期 id，不发送控制 |
| `POST /{batchId}/execute` | `{confirmation,reason}`；只能执行原始完整集合，返回当前进度；不自动重试 |
| `GET /{batchId}` | 只允许发起人且保有相应读取权限，读取内存进度，不发送控制 |
| `GET /operations?resource=job或node&ids=id1,id2` | 最多十个不重复编号；逐项读取持久审计，原有本人/平台审计读取边界不变 |

所有请求拒绝额外字段及未知/重复查询参数。跨集群、跨用户和跨资源读取不能借批量接口绕过原有权限。原生审计 Collection 继续锁定。准备、执行和结果协议见 OpenAPI 0.21.0；原有边界见 [作业取消](jobs.md)、[节点控制](nodes.md) 与[操作审计](audits.md)。

行为参考 [SchedMD scancel](https://slurm.schedmd.com/scancel.html) 与 [scontrol](https://slurm.schedmd.com/scontrol.html)。本项目始终发送明确的单个目标，不调用 Slurm 的批量选择器。
