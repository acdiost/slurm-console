# 节点查询与控制

`/nodes` 查询控制器当前可见的节点，提供表格与状态矩阵、名称/主机名搜索、精确分区和单状态标记筛选、名称/CPU/内存排序及服务端分页。矩阵仅显示当前页。URL 保存集群、筛选、排序、分页、视图、详情和操作编号，可暂停每 10 秒刷新。

详情包含 CPU/内存调度容量及分配量、GPU GRES 与分配量、有效 CPU、OS 报告空闲内存、硬件/Slurmd 版本、特征、分区、备注、预留、状态原因及设置者、启动和维护时间。不可用节点的未分配容量不算空闲；缺失或无法可靠解析的 GPU 数量显示未知。GPU 分配量不是运行时利用率，OS 空闲内存不是可调度内存。

## 授权与服务身份

查询要求目标集群 `nodes.read`；Drain/Resume 分别要求 `nodes.drain` / `nodes.resume`。Operator、Cluster Admin、Super Admin 的已有动作授权仍由后端每次解析；Viewer 不可控制。前端隐藏入口不是安全边界。

节点无“本人所有”范围，不复用作业取消的个人 UID 映射。所有请求使用管理员配置的固定 REST 身份，平台身份和 Slurm 身份不互相模拟。Slurm 的节点更新要求上游管理员权限，普通 REST 身份即使能够查询也可能被拒绝；平台 Super Admin 不自动提升 Slurm 权限。由系统管理员独立决定并提供具备适当管理权限的连接身份，应用及安装器不授予 Slurm AdminLevel、不修改 slurmrestd、Munge 或 Slurm 配置。

## Drain / Resume

- **Drain**：只发送 `state:["DRAIN"]` 和操作原因，阻止分配新作业，允许现有作业继续运行。确认 DRAIN 标记不等同于运行作业已排空。
- **Resume**：只发送 `state:["RESUME"]`，允许节点重新注册并恢复调度。操作原因保留在平台审计；Slurm 自行管理节点状态原因。受理或出现 `NOT_RESPONDING` 不代表已就绪，只有回读确认标准调度状态后才显示“已核实”。

仅接受实际节点名称；拒绝 `ALL`、主机列表表达式、范围、逗号和任意节点属性/信号。没有重启、下电、强制 DOWN、强制 IDLE、修改资源或维护预留的代理端点。已有 DRAIN 不重复 Drain；没有 DRAIN/DOWN 不重复 Resume。未知、无效注册、FUTURE、重启状态不提供普通控制；带预留、维护、故障或电源状态的节点不提供普通 Resume，应先由管理员处理对应流程。备注和预留在此阶段只读。

打开确认框会直接读取最新节点，绕过查询缓存。用户输入完整节点名及 2–300 字单行原因；确认有效 2 分钟，绑定平台用户、集群、动作、节点身份/启动信息、状态、状态原因、已分配资源、维护信息及配置版本。状态/原因变化、权限撤销或配置更新后必须重新校验。

执行前再次核对权限和配置，先把操作意图持久化至 `operation_audits`，再向 `POST /slurm/v0.0.43/node/{node_name}` 发送一次固定更新。审计不可写则不发送请求。控制前后会使节点列表、详情和总览来源缓存失效，进行中的旧快照被丢弃。

## 批量与结果

本页最多选择 10 个节点，选择在切换分页、筛选或集群后清空。批量确认需输入 `DRAIN N` 或 `RESUME N`（N 为本次节点数）及统一原因；所有选中节点通过最新校验后才能提交。浏览器最多并发 3 个逐节点请求，服务端节点校验/控制/核实共享 4 个并发槽。每个请求仍独立校验、独立持久审计，允许部分成功；不会自动回滚其他节点或重试失败写入。服务端单节点执行总时限为连接超时的 3 倍加 1 秒；浏览器断开后已发出的授权请求仍在此边界内完成。

| 结果 | 含义 |
|---|---|
| 正在处理 | 当前应用仍在执行该已持久化的请求 |
| 已核实 | 已回读确认相同节点达到了目标状态；Drain 同时核对原因 |
| 已受理，待核实 | Slurm 已受理，但尚未确认目标状态/重新注册 |
| 未完成 | 明确未发送，或上游明确拒绝身份授权 |
| 结果待核实 | 超时、断网、异常响应、进程中断或完成审计未能保存，不能证明结果 |

操作编号保存在 URL。刷新操作记录只读取状态，不重发写入。当前状态已达到目标不证明它仅由本次操作造成。相同确认重复提交返回同一记录；同节点有 processing/accepted/unknown 记录时禁止新的冲突操作。重启使全部确认令牌失效，持久审计仍可凭操作编号读取。配置版本变化或节点身份变化后不会凭空确认旧请求成功。

批量请求若在进入持久审计前就被拒绝，操作编号可能没有记录，页面会明确提示“尚未送达、已被拒绝或结果待核实”；应核对节点状态和请求日志，不能据此推断成功或自动重发。

## 平台接口

前缀 `/api/v1/clusters/{clusterId}`，所有接口要求活动用户，成功响应统一 `{data,requestId}`，拒绝未知及重复查询参数。

| 方法与路径 | 权限/参数 |
|---|---|
| `GET /nodes` | `nodes.read`；page/perPage/q/partition/state/sort/order |
| `GET /nodes/{nodeName}` | `nodes.read`；返回标准 DTO、资源口径及来源时间 |
| `GET /nodes/{nodeName}/control-context?action=drain或resume` | `nodes.read`；返回最新节点、allowed/message 和短期确认 |
| `POST /nodes/{nodeName}/drain`、`/resume` | `nodes.read` + 对应动作；body={proof,confirmation,reason} |
| `GET /node-operations/{operationId}` | `nodes.read`，且本人操作或 `platform.audit.read`；只读核实 |

节点与作业操作复用锁定原生读写的审计 Collection，各自接口按动作类型隔离，不能借另一资源的读取权限查询审计。审计包含平台操作人、目标节点、动作、原因、请求编号、配置版本、已观察状态和时间。完整平台审计检索与保留策略仍在后续阶段实现。

上游语义及权限依据 [SchedMD scontrol](https://slurm.schedmd.com/scontrol.html)，字段以部署环境提供的 `v0.0.43` OpenAPI 为准，见 [REST 客户端指南](https://slurm.schedmd.com/rest_clients.html)。
