# 作业异常诊断

当前作业和历史作业详情均提供“诊断作业”按钮，按需生成规则诊断。每条发现分别显示事实或解释/待验证、描述置信度、支撑证据及作业用户/管理员的最小核查建议。完整来源事实和证据缺口可展开；不会自动轮询、执行作业控制、读取日志/脚本/环境或调用 AI 服务。

## 来源、身份和权限

- 当前详情：`GET /api/v1/clusters/{clusterId}/jobs/{jobId}/diagnosis`，仅需 `jobs.read`，只按单个数值作业 ID 读取控制器。
- 历史详情：`GET /api/v1/clusters/{clusterId}/job-history/{recordKey}/diagnosis?jobId=...&start=...&end=...`，仅需 `job_history.read`，强制 64 位十六进制记录标识、单个 Job ID 和最多 31 天的提交时间窗口。由历史详情传递实际查询窗口，服务端再次精确匹配记录。

两类来源独立，不互相兜底，也不自动混合查询；无需节点、监控、策略或写权限。不将重复 Job ID、重排队前后、数组元素、异构组件或不同步骤合并成一条时间线。记录 ID、来源观测时间与规则生成时间明确展示，缓存保留原观测时间。历史不存在于指定窗口/Job ID 时返回 404，不能退而诊断另一个记录。

沿用服务器批准的连接、专用 Slurm 身份、现有 Adapter 的范围/格式/数量限制和缓存。当前来源缓存 5 秒，记账 30 秒；共用四个并发槽与 8 MiB 缓存。返回前复查活动用户、当前来源权限、集群启用及配置修订，缓存命中也不跳过；原生权限没有扩大。错误时前端隐藏旧诊断，用户可刷新详情后重新生成。接口见 OpenAPI 0.26.0，无新增 Collection 或迁移。

## 规则 v1

规则区分 Slurm 基础状态与附加标志。基础状态冲突时停止阶段和时间间隔推断；未知状态/原因明确保留未知，不当作正常。CONFIGURING/POWER_UP_NODE 表示节点准备阶段，COMPLETING 为结束清理阶段；没有进入该阶段的确切时间，不断言“卡住很久”。

等待规则覆盖 Priority、Resources、Dependency、BeginTime、保持、Association/QOS 限额、分区状态/限制、节点约束和账户/QOS 可用性等原因组。原因码仅是当前调度尝试呈现的一项原因，不保证唯一根因；Resources 不单独定位 CPU/内存/GPU，空闲节点数或 OS FreeMem 不证明可调度。

终止规则解释 OOM、超时、失败、节点/启动失败、deadline、取消与抢占。置信度高的事实只确认来源确实记录该状态/码，不意味着确认具体硬件、应用代码或事件发起者。主退出记录、派生退出记录与各步骤分别核对，COMPLETED 也不替代业务产物校验；派生退出码可能事后被授权用户调整。

历史记录逐一检查所有已返回步骤（现有每记录最多 512 个）。异常包括失败/异常终止状态、非零退出码或信号；前 20 个异常步骤作为证据展示，并明确总步骤、异常数与已展示数，完整步骤仍在同条历史详情中。步骤不再次计作作业，也不把步骤 CPU 时间加到作业 TotalCPU 上。

## 时间和性能证据

提交至开始、提交至观测、开始至观测的间隔单独标明，不混算为程序 CPU 时间或有效排队时间。当前 PENDING 的预计开始/结束不用于实际运行计算；节点准备阶段不算已经正常执行。历史只使用记账 Elapsed，不把已结束作业向当前时间外推。无效、未知或时间顺序不合法的间隔显示未知。

粗略 CPU 记账占比 = 作业 `TotalCPU / (分配 CPU × 记账 Elapsed)`。仅在已完成、非数组/异构、无 RESIZING/REQUEUED 等相关标志、明确挂起为零且分母有效时计算；总 CPU 或分配缺失、时长为零、分配含歧义时保持 null，结果超过 100% 不截断。这个值不是瞬时 CPU 利用率、作业产出或性能基线。

只有占比大于零且低于 20%、Elapsed 至少 60 秒、没有已知异常退出/步骤时才给出低置信度的性能线索，建议用应用 profile 和同时间轴 CPU/GPU/I/O 指标区分 I/O、锁、串行、线程或 GPU 主导等候选方向。零 CPU 用量可能来自未采集，保留零值但不触发浪费结论。运行中缺少实时资源/进度证据时明确说明缺口。

申请/分配 TRES 不当作实际用量；不将 consumed TRES 误称 MaxRSS 或整作业内存峰值。MaxRSS 通常是步骤中单个任务的峰值，不能直接对比整作业总内存。采样、会计延迟、日志及性能基线仍需管理员按实际站点配置核对。

规则参考 [SchedMD 状态与标志](https://slurm.schedmd.com/job_state_codes.html)、[原因码](https://slurm.schedmd.com/job_reason_codes.html)、[退出记录](https://slurm.schedmd.com/job_exit_code.html)及 [sacct](https://slurm.schedmd.com/sacct.html)，以实际来源和站点版本为准。
