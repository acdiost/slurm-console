# 资源使用报表

`/reports` 按所选逻辑集群的运行时间窗口，汇总 CPU、内存和 GPU 的分配时长估算。支持按用户、Account 或分区分组，三个维度的单个精确值筛选、排序、分页以及全部分组 CSV。全部只读，不创建调度作业、不调用控制、不增加后台采样或安装第三方组件。

## 时间和计量口径

查询必须指定 UNIX 秒区间 `[start,end)`，截至当前、最多 31 天。页面按浏览器本地时间输入和显示，区间本身为绝对时间。报表从 slurmdbd 的作业记录查询运行窗口，使用默认运行时间语义，省略 `usage_time_as_submit_time`；既有历史作业页继续按提交时间查询，两者的服务端缓存键分离。窗口前提交的作业可以成为报表候选，不会因提交时间被过滤。

保留原始起止与时长，在平台内计算交集，不将上游时间截断后误当成原始生命周期。每条可计量记录的资源秒 = 记账 AllocTRES 数量 × `max(0,min(作业结束,窗口终点)-max(作业开始,窗口起点))`。CPU 和 GPU 除以 3600 显示单位·时，内存按 MiB·秒除以 1024×3600 显示 GiB·时。

这是**按记账分配量固定的估算**。历史资源伸缩可能使最终分配量不代表整个区间；本功能没有资源变更时间线，不作为计费、实际 CPU/GPU 利用率、物理核占用或内存峰值。CPU 采用 Slurm 配置的 CPU 单位，可能为逻辑线程；GPU 使用通用 `gres/gpu` 计数，可能包含 MIG 单元，不等于物理卡数。

分配资源分别只采用唯一的通用 `cpu`、`mem`、`gres/gpu` 条目。GPU 型号条目不与通用值叠加，也不替代缺失的通用值。请求量、步骤、TotalCPU 和 consumed TRES 不参加累计。分配数和累计值使用整数及十进制字符串传输，大于 JavaScript 安全整数的值也不丢精度；页面按三位小数显示，小于显示精度的正值显示 `<0.001`，CSV 保留资源秒原值。

## 覆盖与未计量

“窗口来源记录”是当前连接身份可见的来源候选，包含无法确认实际运行区间的记录，不等于去重作业数或全库作业数。可明确判断在窗口外的记录单列数量，不参加分组。Job ID 不作为唯一记录键，复用现有历史记录身份。

时间核查要求明确、单一的已结束状态，提交时间不晚于开始时间，起止合法且结束不晚于来源观测时间，Elapsed 与结束减开始一致，并且明确记录挂起时长为零。活动记录、异构记录、数组父记录/身份不完整记录，以及状态、时间或挂起信息不明确的记录不计量。具有明确数组 ID 和任务 ID 的独立数组任务可计量；步骤始终不重复计数。

同一普通 Job ID 或数组任务身份出现重叠运行区间时，相关记录均不累计资源，归入重叠身份歧义。不同起止但互不相交的独立记录保留，不能据此推断其为不同逻辑作业。已知 RESIZING 等附加标志使状态不再是单一终态，同样不计量。

每种资源独立报告已知/未知记录数；无法计量的记录在三种资源中均计为未知。只有某资源有已知部分时才返回部分累计值，完全未知为 null；缺失资源不补零，真实零保持零。空可见结果显示零和 0/0 覆盖，不能证明整个集群没有消耗。各指标覆盖不足时，页面明确标记“仅已知部分，非完整总量”。

## 权限、来源与边界

新增独立集群权限 `reports.read`，显式授予四类内置角色；自定义角色需管理员显式绑定。报表同时要求 `job_history.read`，任一权限都不能单独取得报表。查询、缓存读取后及返回前复查活动账户、当前两项授权、集群启用和连接修订；浏览器收到查询或导出失败后隐藏旧结果，不能继续导出缓存内容。

来源沿用固定的服务端 Slurm 连接、实际控制器集群名称、专用 Unix socket 身份和现有证书校验；浏览器不能提供实际集群名称、URL、凭据、任意 TRES 或上游条件。结果受 Slurm PrivateData、保留策略、同步延迟及连接身份可见范围限制。不跨逻辑集群合计，多个连接可能指向同一实际集群。

复用 30 秒来源缓存、四个来源并发槽、128 条/32 MiB 缓存限制、8 MiB 上游单响应和最多 5000 条作业。报表请求 `skip_steps=true`；来源不遵守时仍受既有步骤上限约束。超限或来源不完整时明确失败，要求缩小窗口或增加精确条件，不静默截断。每次最多 5000 个分组，前端对完整快照排序并每页显示 20 条，不自动轮询。

没有新报表数据集合、持久快照、定时任务或外部报表服务；仍使用管理员已安装的 slurmdbd/REST。权限随现有数据库备份。

## API 与 CSV

`GET /api/v1/clusters/{clusterId}/reports/usage?start=...&end=...&groupBy=user|account|partition&user=...&account=...&partition=...`。start/end 必填，groupBy 默认 user；拒绝未知/重复参数及多值选择表达式。契约见 OpenAPI 0.28.0。

响应包含报告版本、固定 `execution_overlap_estimate` 口径、实际来源集群、窗口、来源/窗口外记录数、完整汇总和分组，外层保留 fetchedAt、cached 和配置 revision。每行包含记录数、时间核查通过数、四类排除数，以及三种资源的 `resourceSeconds/knownRecords/unknownRecords`。memory.resourceSeconds 的单位是 MiB·秒。

点击导出会重新请求同一受保护接口，重新授权后生成 CSV；导出结果同时更新对应查询缓存。文件包含全部分组，独立于页面排序/分页，另有 `row_type=summary` 汇总行，不能将汇总行和分组行重复求和。每行保留逻辑/实际集群、绝对窗口、来源时间、口径、维度、精确资源秒及覆盖数，空字段表示未知。CSV 使用 UTF-8 BOM、标准引号转义，并将可能被表格程序识别为公式的字段前缀为文本。账户或集群切换导致页面卸载后，未完成导出不会下载旧身份数据。

## 验证

2026-11-02 完成前端 180 项测试、类型检查、lint、生产构建，以及后端完整竞态回归与静态检查（API 352 秒）。额外针对性验证矛盾时间边界。测试覆盖跨窗口裁切、大整数、缺失/零、通用与型号 GPU、步骤不重复计量、独立数组任务、重叠身份、授权分离、跨集群、缓存、查询中撤权/改配置、导出重新授权、CSV 公式转义及全部分组。

虚拟机独立实例使用 11 条合成记录，验证 5 条时间通过记录、CPU 已知部分 50400 单位·秒、内存 95846400 MiB·秒及 GPU 7200 单位·秒；页面展示 9 个用户分组及不同覆盖数，并实际下载 CSV 核对全部分组。真实 Slurm 连接读取既有已取消且未启动的记录，正确保持资源量未知。没有提交、取消或控制真实作业，现有 DOWN 节点未改动。临时实例、连接配置、平台测试账户与凭据在发布前清理。

参考 [SchedMD sacct 字段与时间选项](https://slurm.schedmd.com/sacct.html)。本功能基于作业记录估算，区别于使用记账汇总表的 [sreport](https://slurm.schedmd.com/sreport.html)。
