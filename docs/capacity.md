# 集群容量分析

`/capacity` 展示所选逻辑集群的配置容量、Slurm 调度分配、节点余量、分区对比及历史趋势。它只读取和保存汇总，不执行资源控制，不创建测试作业，不安装监控组件。

## 当前口径

CPU、内存、GPU 分别拆为配置量、已分配、节点余量和不可用容量，满足总量等于后三者之和；未知 GPU 数量与分配保持 null。内存单位为 MiB/GiB。沿用[总览](overview.md)计算，节点 DOWN/DRAIN/无响应/维护等状态的未分配部分计入不可用，有效 CPU 之外的部分也不算节点余量。本项补齐 NOT_RESPONDING、MAINTENANCE 状态别名的判断，影响各页面共用的节点汇总。

调度分配量不等于实际 CPU/GPU 利用率，节点余量也不等于 OS 空闲内存；Slurm 的 OS 空闲内存只供参考，不参与调度。口径参见 [SchedMD sinfo](https://slurm.schedmd.com/sinfo.html) 和 [scontrol](https://slurm.schedmd.com/scontrol.html)。实际 GPU 指标继续由[已有 Prometheus/DCGM 接入](gpu-monitoring.md)提供。

分区表按节点上报的分区归属分别汇总，每个分区内节点去重。共享节点会出现在多个分区，因此不能把表格各行相加为集群总量；没有归属的节点单列为“未归属分区”。按分区名称检索、排序和分页只影响表格，顶部集群汇总及历史趋势不变。分区配置状态额外要求 partitions.read，缺权或读取失败时保留节点容量，配置状态显示未知。

节点余量分布按状态可用节点的 CPU 余量分为 0、1–7、8–31、32–63、64+；单节点最大 CPU/内存余量分别计算，可能来自不同节点。预留、分区限制、QOS、拓扑、资源绑定和作业约束仍影响实际调度，这些值用于容量参考，最终调度由 Slurm 判定。

## 历史与采样

应用对管理员已启用、绑定可信连接方式的集群自动采样，无需浏览器保持打开。每个集群每个 5 分钟桶最多一条，仅保存集群级数值和观测时间，不保存节点名称、作业、用户或分区明细。后台以服务器已批准的固定连接身份读取节点，不借用平台用户身份，也不修改 Slurm。

每分钟按集群 ID 轮转，最多扫描 20 个集群，两个采样槽、每轮 50 秒预算；超时、无效源或容量繁忙时留下缺口，下轮继续，不补写过去的采样。复用现有 Adapter 的上游限制、并发与缓存；样本观测时间来自来源缓存的实际读取时刻，过旧或异常时间拒绝入库。

趋势提供 1 小时、24 小时、7 天窗口，均为截至最近一个完整 UTC 五分钟边界的区间，当前尚未结束的桶稍后纳入。上线前、停机及读取失败的时间保持空白，图形断开；窗口内有效数/应有数明确显示，未把部分覆盖当作全时段结论。刚上线时没有历史图是正常现象，当前容量仍可独立读取。

折线展示已分配、节点余量、不可用容量占配置量的比例，可选择 CPU/内存/GPU。容量加权采样分配比为有效样本的已分配量之和除以配置量之和；采样峰值为有效点的最大比例，最小节点余量同样只针对有效样本。它们是离散采样统计，不是连续时间平均或实际利用率。零配置量无可计算比例，未知 GPU 不参与该资源统计；明细列出窗口、实际观测及配置量。

历史按集群、配置修订及服务端连接方式摘要隔离；配置或 profile 变化后使用新的数据序列，避免不同控制器混算。不跨逻辑集群求和，因为多个连接可能指向同一实际控制器。

保留最近 7 天完整窗口，过期记录后台分批清理。每集群最多 2200 条（含旧版本），全平台最多 100000 条；达到上限时删除较旧记录，窗口覆盖可能不足。原生 Collection 锁定，格式不合法的样本明确返回来源不可用，不当作零值。数据随现有加密数据库备份保存。

## 权限与接口

新增集群动作 `capacity.read`，显式授予 Super Admin、Cluster Admin、Operator、Viewer 四类内置角色，自定义角色不隐式获得。当前容量和历史都同时要求 `capacity.read`、`nodes.read`。分区配置状态另需 `partitions.read`，缺权不访问该来源，也不把已取得的配置内容返回给撤权用户。

来源前后复查当前权限、用户活动状态、集群启用状态和连接摘要；采样写入同样核对配置一致性。跨集群、撤权或停用连接不能读取缓存数据。前端收到任一容量端点 403/404 时隐藏两个数据集并停止自动刷新；当前 Slurm 不可用时，仍可独立读取有权限的既有历史。

- `GET /api/v1/clusters/{clusterId}/capacity`：可用 q、sort(name/nodes/cpuTotal/cpuIdle/memoryTotal/gpuTotal)、order、page、perPage；返回当前汇总、节点分布、分页分区及独立配置来源状态。
- `GET /api/v1/clusters/{clusterId}/capacity/history?range=1h|24h|7d`：只读应用数据库，无 Slurm 请求；返回固定桶、null 缺口、覆盖数及分资源统计。

拒绝未知/重复查询参数。历史最多 2016 点、四个并发读取槽和 5 秒数据库读取预算；节点最多 20000，分区归属最多 512 类/100000 次关系，超限明确失败，不静默截断。缓存命中仍检查权限。接口见 [OpenAPI 0.24.0](../api/openapi.yaml)。本页也支持按用户及集群保存筛选方案，包括趋势窗口、资源和分区表条件。
