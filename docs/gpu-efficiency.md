# GPU 资源效率分析

`/gpu-efficiency` 基于[已有 GPU 监控接入](gpu-monitoring.md)的管理员配置，读取物理 GPU 的窗口利用率、显存占用及功耗，提供逐卡排序、覆盖、低利用率线索和整体趋势。接口只需集群 `metrics.read`；不查询 Slurm 节点/作业、不推断 GPU 与作业的分配关系、不执行控制。页面支持按用户和集群保存具名筛选方案。

正式监控源仍待管理员配置，本次用隔离 HTTP 协议数据完成验收；虚拟机没有 GPU，不宣称完成真实硬件采集。未配置来源显示明确状态和未知值，不填入演示数据，也不安装 Prometheus/DCGM 等第三方服务。管理员可按[监控接入说明](gpu-monitoring.md)配置既有来源。

## 窗口与统计

仅接受 1/6/24 小时，步长分别为 60/300/600 秒，窗口截止最近一个完整步长边界。评估点为 start+step 至 end，每卡应有 60/72/144 点。每点采用 `last_over_time(固定指标{精确集群标签}[60s])`，保留缺口，不用 Prometheus 默认回看填充。6/24 小时是稀疏采样；有效点数 / 应有点数是**采样覆盖**，不等于连续时间覆盖，样本不足不能认定空闲。

参考 [Prometheus 范围函数](https://prometheus.io/docs/prometheus/latest/querying/functions/)及 [NVIDIA DCGM Exporter 字段说明](https://docs.nvidia.com/datacenter/dcgm/latest/reference/dcgm-exporter-metrics.html)。沿用管理员声明的 percent/ratio 单位和现有固定经典指标名，需按来源 `/metrics` 核对。利用率描述 GPU 指标采样，不等于作业产出、SM/Tensor Core 效率或 Slurm 分配率。

每个物理 GPU（节点 + UUID）分别计算：

- 利用率：有效点算术均值、最近秩 P95（排序后第 ceil(0.95×有效点数) 个）、采样峰值。
- 低利用率样本：利用率严格低于 20% 的有效点数及其占有效点的比例。至少 80% 应有点有效，且低利用率有效点占比至少 80% 时显示“低利用率线索”。覆盖充足但未达条件显示“未达低利用率条件”；其余为“利用率采样不足”。边界 20% 不属于低利用率，零是有效值。
- 显存占用：同一评估点 USED / TOTAL，TOTAL 正数且 USED 不超过 TOTAL 才有效。仅在整条 TOTAL 序列未出现时，允许同一点 USED + FREE 作为总量。保留每项独立覆盖，不用 GPU 利用率的覆盖替代显存或功耗覆盖。
- 功耗：有效瓦数样本均值、P95 和峰值；不将稀疏功耗外推为耗电量，不用利用率除以功耗宣称性能功耗比。

均值、P95 和峰值只包含有效样本，不插值、不补零。无有效点时指标为 null；零分母的显存比为 null。低利用率仅为排查线索，需要结合负载阶段、显存及调度判断，不自动释放资源、不发通知、不归因到用户或作业。

## 整体与身份

整体卡数仅表示窗口内有可识别序列的物理卡，不代表硬件库存；只有显存或功耗的 GPU 也计为观测卡，但利用率采样不足。总体均值按所有无身份冲突的有效 GPU 利用率样本等权计算；每个趋势点按该点有效 GPU 等权平均，同时返回参与卡数，未知点断线。观测集合及每点参与卡数可变化，不外推为整个集群的连续时段结论。

分区/Slurm 分配与本项无逐卡对应关系。表格按节点、UUID、型号检索，按均值、覆盖、低样本占比、显存或功耗排序，支持结果筛选和分页；整体汇总与趋势保持当前窗口全体口径。未知排序项始终排在末尾。

同一指标多条序列、同一 UUID 跨节点、型号或索引冲突均令整卡统计未知，并显示身份冲突，避免聚合隐藏重复来源。MIG/未映射主机序列不合入物理卡，返回忽略数量。未知/NaN/Inf/异常范围和缺失点均不当作零。管理员需保证物理卡 UUID、节点映射和采集标签正确。

## API 与边界

`GET /api/v1/clusters/{clusterId}/metrics/gpu/efficiency?range=1h|6h|24h`，可加 `q/status/sort/order/page/perPage`，见 OpenAPI 0.25.0。拒绝未知/重复参数；q 为最多 128 UTF-8 字节的字面匹配。范围和排序白名单固定，浏览器不能提供 PromQL、URL 或凭据。

最多 512 个物理 GPU；分五次固定指标 query_range 查询，每次最多 4 MiB、4096 条序列、120000 点，超限、警告和越界时间明确失败，不截断统计。20 秒总查询预算，与现有监控共用四个并发槽、64 项/8 MiB 缓存上限，分析缓存 30 秒；每次返回前复查用户活动状态、当前授权、集群启用状态及配置修订。前端错误时隐藏旧数据，403/404 停止自动刷新。原有监控页面和趋势保持兼容。

分析仅在内存中生成和短期缓存，不新增数据库采样或后台任务；保留与源查询的真实窗口及查询时间。不安装外部组件，不触碰现有告警规则。
