# 配置变更对比

本项覆盖**平台管理的集群连接配置**：在 `/clusters` 新建、编辑和停用前预览字段差异，在 `/configuration-history` 比较该集群任意两个已保存版本。Slurm 配置文件、QOS/TRES 策略、服务端 profile 文件和认证配置不属于这套版本模型。

## 保存前预览

新建和编辑填写完成后点击“预览变更”，服务端使用与实际保存相同的规范化和校验逻辑，返回当前/拟保存配置、完整七字段对比及前后版本号。确认框展示规范化后的内容，只有点击“确认保存”才发送原有创建或更新请求；“返回编辑”保留草稿。停用按钮同样先读取并展示启用到停用的变化，再显式确认。

预览不保存集群、审计或版本，也不检测连接、不访问 Slurm。它是只读预览，不产生授权令牌或执行许可。原有管理 API 保持兼容，实际保存仍独立校验请求、当前管理权限及乐观版本；预览后其他人修改配置会使旧 revision 被拒绝，需关闭编辑并刷新后重新预览。预览并不锁定配置，也不替代保存时的检查。

对比字段固定为名称、不可变标识、说明、连接方式引用、REST API 版本、平台连接启停和超时。显示当前真实字段，不使用连接 DTO 的默认超时替代未配置的原始零值。新建时旧值为 null，界面显示“不存在”；已保存的空字符串显示“空值”，false/0 保持实际含义。可切换只显示变化或显示全部字段。

## 基线、版本与审计

新增锁定的 `cluster_config_versions` Collection。迁移为每个既有集群保存**迁移时当前配置**的一条 baseline，沿用当时 revision，允许尚未配置连接的 v0。基线记录时间是此次采集时间，原始操作人、请求和审计编号留空；不把当前管理员、旧创建时间或不完整的旧审计当成原始证据。迁移重复运行不会新增基线，也不修改现有配置。

此后受支持的连接创建、更新、停用及 CLI `access register-cluster` 登记，将配置、成功审计和字段快照置于同一事务，任一步失败则全部回滚。版本保存记录时的操作人 ID/名称/来源、请求编号、审计操作编号、动作、schemaVersion 和记录时间，不使用当前用户名称回填历史。本机 CLI 记录进程有效 UID，不推断 SSH 登录人。

`(cluster_id,revision)` 唯一；相同版本重复捕获只能与已存内容一致，不会覆写既有来源。即使一次保存的业务字段没有变化，revision 仍可递增并留痕；字段对比忽略版本号、记录时间和操作人，因此这种情况明确显示“配置字段相同”。比较两个相隔多次修改的版本只表示快照差异，不能把全部差异归因于其中某一条审计。

快照不解析 profile 引用，因而不保存或返回 endpoint、认证身份、token、凭据/证书文件路径或内容；不包含 last_probe 等连接检测结果。连接检测和周期探测不生成新版本。说明字段现在也包含于连接变更审计，仍通过既有标量白名单读取。

历史集群和用户标识采用文本存储，集群删除、停用、改名、profile 移除或用户消失都不级联删除版本。历史版本可以凭保留的集群 ID 查询，无需借用当前集群资源读取权限。页面可跳转到关联审计。

## 当前状态与覆盖边界

历史列表读取时对比当前记录与最新快照，返回以下状态：

| 状态 | 含义 |
| --- | --- |
| matched | 当前 revision 和七字段与最新快照一致 |
| different | 当前记录与最新快照不同，可能存在未记录的修改 |
| missing | 当前集群已不存在，保留版本仍可读取 |
| no_history | 当前集群存在但尚无快照，不补造基线 |

这里只读比较，不提供回滚、恢复、重放或应用历史版本。版本编号可能不连续，不从旧审计反推缺失快照。直接数据库修改、原生超级用户操作、外部文件修改以及未经过受支持写入入口的内部调用不在捕获范围内；快照记录的是保存时状态，并不能证明差异均由某一人造成。本地数据库管理员仍可修改记录，本功能不提供防篡改证明。

不自动清理或提供浏览器删除版本接口，版本随现有加密数据库备份保存；回退需恢复匹配的完整备份，不执行破坏性 down 迁移。

## 权限与 API

预览和实际管理要求活动用户具备平台范围 `platform.clusters.manage`；历史列表和比较同时要求 `platform.audit.read`。Cluster Admin、Operator、Viewer 的集群角色不隐式获得这些平台权限。未授予审计权限的配置管理员仍可预览当前草稿，但不能查看历史操作人及快照。

历史接口读取数据库后重新解析当前授权与用户活动状态；返回前不因缓存或旧令牌沿用权限。前端查询按用户和集群隔离，任何查询错误隐藏旧版本与差异，服务端拒绝管理操作后也隐藏旧配置界面。原生版本 Collection CRUD 对平台角色全部锁定。

前缀 `/api/v1/cluster-configurations`，契约见 OpenAPI 0.29.0。

| 方法与路径 | 输入与作用 |
| --- | --- |
| `POST /preview` | 与创建相同的完整配置及 revision=0；只读创建预览 |
| `POST /{clusterId}/preview` | 与修改相同的完整配置及当前 revision；只读修改预览 |
| `POST /{clusterId}/disable-preview` | `{revision}`；只读停用预览，profile 移除后仍可使用 |
| `GET /{clusterId}/versions` | page/perPage，默认 20、最大 100；版本倒序元数据、当前状态与来源时间 |
| `GET /{clusterId}/compare?from=...&to=...` | 两个明确版本记录 ID；读取两个快照和七字段差异，允许反向及同版本比较 |

成功响应保持 `{data,requestId}`。预览拒绝未知字段与查询参数；历史拒绝未知/重复参数，历史接口的 clusterId 和版本 ID 为 15 位小写字母/数字。比较只在同一集群内定位版本，跨集群或缺失版本返回 404。历史页可跨分页选择版本，URL 保留集群、页码和已比较的版本 ID。列表和比较使用有界数据库查询及五秒读取预算，不访问 Slurm、不自动轮询，原生 Collection 无浏览器写入路径。

## 验证

虚拟机隔离数据库先由上一正式版创建 v1 配置，再升级新程序，验证只产生一条无虚构操作人的基线。界面预览名称、说明、超时三项差异，确认后生成 v2；停用预览确认后生成 v3。任意版本对比与审计关联均核对；隔离服务重启后 v1/v2/v3 保留且不重复建立基线。原有 Slurm DOWN 节点和空队列未改动。临时环境、平台测试账户与凭据在发布前清理。
