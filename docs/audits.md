# 操作审计

`/audits` 检索应用数据库中的 `operation_audits`，支持文本搜索、精确集群/操作人/动作/结果、时间范围、创建或更新时间排序和服务端分页。URL 保存筛选、分页及详情编号。默认手动刷新，也可每 15 秒刷新；查询错误会隐藏旧列表/详情。当前页可导出 JSON，包含查询条件、来源时间、总条数及本页数据，最多 100 条，不等同于完整备份。

## 权限与历史证据

列表和详情独立要求活动平台用户及平台范围 `platform.audit.read`。默认 Super Admin 具备该动作，集群管理员、Operator、Viewer 不因此获得平台审计权限。每次请求重新解析授权，原生 Collection API 对所有平台角色锁定。接口只读，没有新增、编辑或删除审计的浏览器 API。

审计可跨集群读取，不依赖当前 `clusters.read/jobs.read/nodes.read`，因此集群停用、删除、用户更名或目标消失后仍可查看证据。审计权限不授予当前资源读取/控制权限。详情的当前资源链接按相应动作显示，目标接口再次授权。原有 job-operations/node-operations 接口继续保留本人和资源范围限制。

新操作在意图时保存操作人 ID/名称、来源、集群 ID/名称/标识、目标类型/ID、配置版本、动作、原因、操作编号、请求编号及时间。外部控制另保存已观察的 Slurm 状态。本机命令记录进程有效 UID（`local:uid:UID`），不推断 SSH 登录人或 sudo 发起人。旧记录缺少快照时显示 ID 和来源未知，不用当前名称冒充历史名称；不从旧日志回填不存在的证据。

## 覆盖范围与事务

| 操作 | 持久化方式 |
|---|---|
| 作业取消、节点 Drain/Resume | 先保存操作意图，再发送一次 Slurm 更新；完成或核实后更新结果 |
| 集群连接创建、更新、停用 | 平台配置变更与成功记录在同一事务提交 |
| `users create/create-pam/create-ldap/link-pam/link-ldap` | 账户变更与成功记录在同一事务提交 |
| `access grant/revoke/register-cluster` | 授权/登记与成功记录在同一事务提交 |
| `slurm-identity link/unlink` | 映射变更与成功记录在同一事务提交 |

平台事务写审计失败则回滚业务变更；外部控制仍在审计失败时拒绝发送请求。重复的本地幂等命令可以记录一次“命令完成”，不代表产生新授权，前后值可相同。字段变更采用服务端白名单，只保存管理所需的非敏感值，不保存密码、Token、凭据路径、LDAP 唯一标识、REST endpoint、确认 proof、输入哈希或资源指纹。账户创建不记录密码哈希。

只读连接检测及周期探测不生成管理变更审计；原有请求日志继续记录请求编号、调用人、路径与 HTTP 结果。未通过校验/授权而没有管理变更的请求不伪造成功证据，失败请求通过请求日志排查。原生超级用户、直接数据库修改和第三方系统自身操作不在平台管理 API 的审计覆盖内。

## 结果语义

| 展示 | 持久状态 | 含义 |
|---|---|---|
| 已完成 | succeeded | 平台数据库变更/本地命令已提交，不表示 Slurm 资源改变 |
| 已核实 | confirmed | 控制功能曾回读核实目标状态，见作业/节点文档 |
| 已受理，待核实 | accepted | 上游受理，尚未确认目标结果 |
| 未完成 | failed | 明确未发出或上游明确拒绝 |
| 结果待核实 | unknown / processing | 无法证明完成；processing 也可能为中断遗留 |

审计查询只读取已保存证据，不访问 Slurm、不调用控制服务的核实方法、不改变记录更新时间，不重发写入。详情保留 `recordedStatus` 供区分原始 processing，统一保守显示 unknown。未知结果筛选包含 processing。当前资源状态变化不能反向证明历史操作成功。

## API

- `GET /api/v1/operation-audits`：`page` 1–1000000、`perPage` 1–100；`q` 最多 255 字节，按操作/请求编号、目标、原因、操作人和集群快照作子串匹配；`cluster`、`actor`、`action` 精确匹配；`status` 支持 succeeded/confirmed/accepted/failed/unknown，以及原始 processing；`sort=created|updated`、`order=asc|desc`，默认创建时间降序，同值以内部 ID 稳定排序。
- `from` 包含、`to` 不包含，均为含时区的 RFC3339 时间，最多毫秒精度。按记录创建时间过滤，转换为 PocketBase UTC 毫秒格式后比较。前端按浏览器时区输入，URL 保存 UTC。
- `GET /api/v1/operation-audits/{operationId}`：凭外部操作编号精确读取，无查询参数；不存在返回 404。

成功响应统一 `{data,requestId}`；列表包含 items/page/perPage/totalItems/fetchedAt，详情包含 item/fetchedAt。列表计数和本页在同一事务快照读取，最多 5 秒；查询取消/超时返回 408。查询值参数绑定，拒绝未知、重复、超长及非法参数。

## 保留与备份

迁移只增加字段和索引，保留现有证据；不自动清理历史。审计属于应用 SQLite 数据，数据库文件的管理员仍可修改它，当前不提供防篡改签名或外部审计汇集。管理员应按 [部署说明](deployment.md) 备份一致的应用数据，并将备份/导出留存在独立位置；加密快照、每日调度及完整恢复工具见 [备份与恢复](backups.md)。
